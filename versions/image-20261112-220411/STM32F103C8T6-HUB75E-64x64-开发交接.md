# STM32F103C8T6 驱动 64×64 P2.5 HUB75E 灯板：开发交接

更新：2026-11-12 ｜ 阶段：照片及资料已核对，实物接线、上电和波形尚未验收。

**先接对三件事：** 灯板用你的可调电源单独供电，设为 **5.0 V**，接灯板独立电源座；**16 针 HUB75E 没有 5 V 供电脚**。STM32、灯板、电平转换器和 ST-Link **共地**。先断电确认 **HUB75E 输入座与 Pin 1 的物理方向**，再按表飞线。

当前设备：用户已有 ST-Link 连接 STM32，另有独立可调电源给灯板供 5 V。STM32 实际供电来源、ST-Link 型号、可调电源在 5 V 档的持续电流能力尚未确认。本交接以 STM32F103C8T6 为开发目标。

## 2. 电源与 ST-Link：按现有设备接线

```text
可调电源 +5.0 V ── 足额电源线 ── 灯板独立电源座 VCC
                └── 同一灯板 5 V 支路 ── 两片电平转换器 VCC
可调电源 GND ──── 足额回路线 ── 灯板独立电源座 GND
                └── 信号参考地 ── 转换器 GND ── STM32 GND ── ST-Link GND
STM32 核心板供电：按板型使用已确认的独立电源入口，例如核心板 USB
电脑 USB ── ST-Link ── SWDIO / SWCLK / GND（按型号另接 VTref、NRST）
STM32 GPIO ── 3.3 V → 5 V 缓冲 ── HUB75E IN
```

- 面板主电流从独立电源座返回可调电源。HUB75E 的 Pin 4、16 都作为信号地接入共地；主回流不走杜邦线、ST-Link、MCU 小板或转换器。5 V 正线不接 MCU GPIO、3V3、SWD 接口或 HUB75E。
- 5 V 是本方案的灯板供电目标。微雪同规格产品标称 **5 V / 4 A**，可作单板台架电源的能力参考（约 20 W），并非这块 PCB 的实测电流或上限。优先使用在 5 V 下可连续输出 4 A 或以上、且有余量的电源和合适线材；若现有电源容量较小，仅在限流下做低亮度验证。提高负载前看灯板端电压与电流；电源进入恒流模式、板端明显掉压或局部异常发热时，先消隐、关输出并排查。不要提高设定电压补线损。
- 调电源时先关闭输出并断开灯板，设 **5.0 V**、设置适合初次低亮度调试的保护限流，并用万用表核对极性。两边断电时测电源座与已知地、输入座地针及电容负端的连通性；正端用 `VCC`/`+`、走线和电容正端交叉确认。排除持续低阻短路，留意电容充电可能引发的短暂蜂鸣。禁止带电插拔或移动飞线。
- 灯板、转换器与 MCU 可能先后上电。用第 4 节的禁用/消隐方案；尽量避免一侧断电时另一侧持续向其信号脚驱动。独立电源的通断组合要实测，不能把缓冲器的三态功能等同于任意断电隔离。

| ST-Link 端信号 | STM32F103C8T6 核心板侧 | 说明 |
| --- | --- | --- |
| SWDIO | PA13 / SWDIO | 保留给烧录及调试。 |
| SWCLK | PA14 / SWCLK | 短线，与 GND 一起接。 |
| GND | GND | 必接，并与灯板共地。 |
| NRST / RESET | NRST | 若探针提供，建议接，方便 Connect Under Reset。 |
| VTref / VAPP / T_VCC（若为目标电压检测输入） | 核心板已供电的 3V3 | 电压参考，不给核心板供电。 |
| 3.3V OUT（仅在确认是供电输出时） | 可选接核心板规定的 3V3 供电入口 | 先核对探针额定电流、板型及供电方式；若核心板由 USB 或其他电源供电，不并接此输出。 |

ST-Link 不同型号和仿制款的针序、`VCC` 含义都可能不同。以手中探针标识和资料为准，先独立确认核心板 3.3 V 和 SWD 连接成功；不要只因为 ST-Link 插了 USB 就认定目标板已上电。刷写、单步或停在断点前让灯板保持消隐或关闭灯板电源，避免程序停在 OE 低电平时持续选通同一行。

## 3. HUB75E 逐针飞线表

以下为**照片丝印信号 + 沿用原讨论的 MCU GPIO 分配**。连接方向是 STM32 → 电平转换 → 灯板 **IN**。GPIO 是工程分配，和灯板厂商无关。

面对照片里的 **PCB 背面插座插合面**、板号文字保持在插座下方时，丝印矩阵的左列为奇数、右列为偶数，从上向下编号。照片上端左侧可见方形焊盘轮廓，是 Pin 1 候选；**安装前必须在实物上核对方焊盘或 1/三角标记、缺口、线缆端导通及地针**。看母头线缆背面容易镜像，红边也只是线缆标记。若两座都有信号表，依据 PCB 的 IN/OUT 标识、箭头、资料或走线确认输入；地针导通只能核对地和方向，不能判断 IN/OUT。

| HUB75E Pin | 信号 | STM32 GPIO / 接点 | 用途 |
| ---: | --- | --- | --- |
| 1 | R1 | PA0 | 第一组红色数据 |
| 2 | G1 | PA1 | 第一组绿色数据 |
| 3 | B1 | PA2 | 第一组蓝色数据 |
| 4 | GND | 共地 | 信号参考地 |
| 5 | R2 | PA3 | 第二组红色数据 |
| 6 | G2 | PA4 | 第二组绿色数据 |
| 7 | B2 | PA5 | 第二组蓝色数据 |
| 8 | E | PB12 | 行地址 bit 4；此板丝印为 E，不能接地 |
| 9 | A | PB0 | 行地址 bit 0 |
| 10 | B | PB1 | 行地址 bit 1 |
| 11 | C | PB10 | 行地址 bit 2 |
| 12 | D | PB11 | 行地址 bit 3 |
| 13 | CLK | PA6 | 数据移位时钟 |
| 14 | LAT / STB | PA7 | 锁存 |
| 15 | OE | PA8 | 灯板输出使能；按低有效起步，低亮度实测确认 |
| 16 | GND | 共地 | 信号参考地 |

GPIO 端用短线，优先做有防反插的 2×8 转接板/线束；注意 CLK、LAT、OE 的地回路。线序、方向、每针导通和相邻针不短路核验后，拍一张带 Pin 1、IN 和电源极性标记的实物图放进工程。

## 4. 3.3 V → 5 V 电平转换和复位消隐

**建议首版就加两片 SN74AHCT245，14 路全部转换。** TI 的 AHCT245 推荐供电范围为 4.5–5.5 V，高电平输入要求 `VIH(min)=2.0 V`，低电平 `VIL(max)=0.8 V`。同系列名下的 **74HC245 不是等价替代**：HC 输入是 CMOS 门限。例如 TI SN74HC04 在 **VCC=4.5 V** 时要求 `VIH(min)=3.15 V`；ICN2012 的手册给出 `VIH(min)=0.7 × VDD`，在 5.0 V 时是 3.5 V。这些是器件输入条件，不能推出每个 HUB75E 针直连哪颗芯片。即使某块灯板用 3.3 V 直连偶尔能亮，也不能证明有足够噪声裕量。

| 缓冲器 | 建议分配（通道从 A 到 B） |
| --- | --- |
| U1 | 1–8：R1、G1、B1、R2、G2、B2、CLK、LAT |
| U2 | 1–6：A、B、C、D、E、灯板 OE；A7/A8 接地，B7/B8 悬空不接 |

- 两片 `DIR` 固定高电平（A→B），A 侧接 STM32，B 侧接灯板；每片 VCC–GND 就近放 100 nF 去耦，按所购封装核对引脚。对需要在 MCU 复位时也有确定电平的 A 侧输入加弱上/下拉：OE 输入可上拉到 **MCU 的 3.3 V**，CLK/LAT 等其余线可下拉。禁止将 A 侧 GPIO 上拉到 5 V。
- **区分两个 OE：** 灯板 OE 是 PA8 经缓冲后的扫描消隐信号；两片缓冲器的低有效 `/OE_245` 是输出三态控制。参考做法：两片 `/OE_245` 并接，用约 10 kΩ 上拉到本地 5 V，另用 3.3 V 栅压下能可靠导通的小信号 NMOS 开漏拉低。NMOS 源极接地，栅极用约 47–100 kΩ 下拉；可由空闲且已核实引出的 **PB13（`SHIFT_EN`）** 控制，高电平启用输出，低电平或复位时禁用。PB13 不接 HUB75E。这样 5 V 上拉不会直连 MCU。
- 缓冲器高阻期间，灯板侧 Pin 15 以约 4.7–10 kΩ 上拉至**灯板本地 5 V**，以期保持熄屏。实施前确认灯板输入没有冲突驱动或强下拉，上电后实测 Pin 15 电压和屏是否熄灭。必要时对屏侧 CLK/LAT 加弱下拉，避免缓冲关闭期间漂浮。阻值是原型起点，不能替代实测。不要将两片 `/OE_245` 永久接地来跳过复位检查。
- MCU 先把 PA8 设高、其他信号设到空闲，再使 `SHIFT_EN` 生效；保持消隐，移入并锁存全零数据后再运行扫描。故障或暂停时先消隐，再禁用缓冲。上述默认电平解决复位时的输出状态，不能自动解决 CPU 卡在点亮相位：实际接屏时应避免断点停亮；后续可用定时器硬件限定 OE 低脉宽。
- 电源切换和一侧掉电时要核对实际器件的掉电高阻/`Ioff` 规格。不能假定 SN74AHCT245 在 VCC=0 时的 A/B 所有端口都隔离。需要支持独立热切换时，按两边电源有效状态做互锁并选有明确掉电保护的器件，验证无反灌后再使用。
- 若实测 CLK 有过冲、振铃或多次越过门限，先缩短信号线和改善地回路，再试在缓冲输出源端串联约 22–47 Ω，依据波形调整。波形从灯板 IN 端测，仪器输入应能承受 5 V。

## 5. CubeMX 初始化

1. 新建 MCU 工程，选 `STM32F103C8T6` 对应目标；工程内保存 `.ioc`、实际生成器及 STM32CubeF1 包版本。SYS → Debug 选 **Serial Wire**；保留 PA13/PA14 和 NRST。启动设置使用从用户 Flash 启动的板型配置。
2. 先用 HSI 点亮及验证 SWD；若确认核心板安装 8 MHz 晶体，选择 HSE Crystal/Ceramic Resonator（若实际是外部有源时钟才用 Bypass），可用 PLL ×9 得到 72 MHz。该配置下 AHB=72 MHz、APB1=36 MHz、APB2=72 MHz，Flash 延迟按 CubeMX 与手册配置。TIM2/TIM3 在此 APB1 分频下定时器时钟为 72 MHz；换时钟配置时必须重算。
3. 表内 14 个信号全部设 `GPIO_Output`、推挽、无内部上下拉，标签可用 `HUB_R1`…`HUB_OE`；若装了缓冲使能电路再配 PB13。`HUB_OE` 初值 High；RGB、A–E、CLK、LAT 和 `SHIFT_EN` 初值 Low。使能 GPIOA/B 时钟后，**先写输出锁存状态，再把引脚切为输出模式**；检查生成的 `MX_GPIO_Init()` 确实按此顺序。固件初值不能替代上电期间的硬件默认状态。
4. F1 的 GPIO Speed 是输出级的速度配置。先从满足低速调试的档位起步，根据信号在灯板侧的上升沿和时序再提高。原讨论的 High 可作高速调试选项；不要把它理解成扫描频率。示波器实测前不要追求最高速度。
5. 首版可用 TIM2 做行节拍，或用计数器测量并在轮询中按微秒延时。不要用 `HAL_Delay()` 实现行时序。例：若 TIM2 输入 72 MHz、PSC=71，计数频率为 1 MHz（1 µs/tick）；HSI 8 MHz 且无总线分频时相应可用 PSC=7。定时中断版本要验证最坏执行时间和中断抖动。
6. 先将灯板信号线与 MCU 隔离（两边断电时拔线），独立给核心板供电，用 ST-Link/CubeProgrammer 读设备并验证写入；失败先查供电、GND、SWDIO/SWCLK、降低 SWD 频率，再尝试 Connect Under Reset。移植示例前检查 SPI1、USART、ADC 等是否与所选 GPIO 重叠。启动正常后保存可复现的编译、烧录方式。

## 6. 1/32 扫描和时序

工作模型：A–E 形成 0–31 的行地址；每次显示两个物理行，一般是 `row` 和 `row+32`，分别使用 RGB1、RGB2。六根数据线在每个 CLK 同时送出两组 RGB 位，**每个行地址、每个位平面送 64 个 CLK**。这是首版假设；真实行对、列移位方向、RGB 次序用单点/行列图案确认。灯板要持续扫描，没有可供 MCU 一次写入并自动刷新的标准 I²C/SPI 显存接口；单路 SPI MOSI 也不能直接代替六路并行颜色。

```text
for row = 0..31:
    OE = 1                        // 消隐，保留关断保护间隔
    A..E = row                    // A 为 bit 0，E 为 bit 4
    repeat 64 times:
        写六位 RGB                // CLK 为低，预留数据建立时间
        CLK = 1                   // 先按上升沿采样实现
        CLK = 0                   // 满足保持时间和 CLK 脉宽
    LAT pulse                     // CLK 保持低，先按高脉冲实现
    等待行地址和锁存稳定
    OE = 0 持续 t_on              // 低有效模型；亮度从很低开始
    OE = 1                        // 下一行或剩余空闲时间保持消隐
```

首版在消隐时完成地址切换、全部移位和 LAT；以波形确认极性、脉宽、建立/保持时间。没有模组级时序资料，不要直接把其他板的门限或 CLK 上限写成此板的规格。若上/下屏交错、周期性错行或重影，先测 A–E、OE、LAT 的先后；试验调整地址与 LAT 的顺序时始终保持消隐。验证移位寄存器和输出锁存独立后，可尝试显示本行期间预移下一行，仍在消隐窗口切地址和锁存。

**时序预算（原型估算，不是实测）**

- 1 位颜色：固定行槽 250 µs，32 槽一帧约 **125 Hz**。若实测 CLK=1 MHz，则 64 列移位约 64 µs；加上消隐保护、锁存、代码开销和点亮时间，总和必须落在 250 µs 内。初次短脉冲可试每槽 5–10 µs，其余时间消隐；若不亮，先确认波形，再小步延长脉宽。
- 进阶亮度：每个颜色通道按位平面输出，点亮时间可用 `t_unit × (1 << p)`，全局亮度再调 OE 有效时间。每次点亮的最短脉宽要在实物可可靠显示的范围内。未做移位重叠、每个行地址均刷新 B 个平面时，可用 `T_frame ≈ 32 × [B × (64 / f_CLK + t_guard) + t_unit × (2^B − 1)]`，其中 `t_guard` 包含切行、锁存、消隐和每平面额外软件耗时。例：B=4、1 MHz、保护开销 10 µs、单位点亮 10 µs，约 14.27 ms/帧，即 **70 Hz**。先测刷新率，再决定提速或减灰度位数。
- 1 位版建议以 **实测整帧 ≥100 Hz** 作为工程验收目标。用帧起点标记或重复行地址的周期测量，不能用 CLK 频率或单行频率代替。多灰度版另定目标，记录最低灰阶、整帧频率与重影；人眼与相机表现需分别观察。

## 7. 软件架构与内存预算

- 第一阶段：HAL 做初始化，GPIO 轮询做低亮度诊断，不先做 DMA 或灰度。每次只变一个变量，先行对与单点，再纯色。确认 GPIOA 的 PA0–PA5 数据掩码后，内层可用 32 位 `GPIOA->BSRR` 一次设/清六路，再单独拨 CLK；GPIOB 的 A–E 也用掩码和 BSRR 更新。不得整端口写 ODR 覆盖无关脚。CLK/LAT/OE 与数据虽同在 GPIOA，写掩码必须互不干扰。
- 第二阶段：建立独立扫描调度和绘图层。扫描器管理消隐、移位、锁存、行槽与亮度；绘图层负责逻辑坐标。将行/列/颜色映射集中到一处。实时路径避免日志、阻塞 I/O 和堆分配；在帧边界提交更新，单帧缓冲可用行缓存或明确同步策略控制撕裂。
- 第三阶段：用定时器限制点亮窗口，再评估 GPIO BSRR 波形流和 DMA。F103 DMA 请求与通道固定映射，需按 RM0008 核对实际 TIM 请求、DMA 通道冲突、GPIO 目的寄存器访问、32 位数据宽度、事件顺序及完成中断。DMA 若把数据和 CLK 同时切换，仍须检查建立/保持时间；建议先证明小波形，再做行级双缓冲。若改用 PA8/TIM1_CH1 生成 OE，另查复用、极性、空闲电平和停止行为；首版 PA8 仍作普通 GPIO。
- STM32F103C8T6 预算：Flash **64 KiB**、SRAM **20 KiB**、最高 **72 MHz**。RGB565 单缓冲 `64×64×2=8,192 B`；双缓冲 `16,384 B`，只余 4,096 B 给其他静态变量、栈和 DMA。每槽的 64 个 32 位 BSRR 字仅单个步骤就 256 B；若每像素用 3 个字，单行/单平面是 768 B，32 行单平面全展开已 24,576 B。优先逐行生成小缓冲、单 framebuffer、Flash 常量字体；用链接 map 核对静态占用并留栈余量。RGB565 是存储格式，实际显示灰度位数由时序预算决定。

## 8. 上电任务与验收

当前所有硬件验收项均未执行。先完成 A–D，再做全屏和负载测试。

| 步骤 | 操作 | 通过标准 |
| --- | --- | --- |
| A. 断电核验 | 确认 IN、Pin 1、Pin 4/16 地、Pin 8 E、供电正负和 14 路端到端导通。 | 有标注照片和针脚记录；无持续短路、反插或把 E 接地。 |
| B. 只测核心板 | 用已确认的电源给 MCU 供电，ST-Link 通过 SWD 识别目标、烧录并校验。 | 目标 3.3 V 正常，程序可启动，SWD 可重新连接。 |
| C. 供电与消隐 | 接共地和电平转换器，限流启用灯板 5.0 V。检查上电、复位、禁用和断电组合。 | 实测灯板端电压及空白电流；OE 应处于消隐电平，屏无闪亮或异常发热；没有通过信号线给掉电侧反灌。 |
| D. 捕获波形 | 在 IN 端同时测 CLK、LAT、OE，分次补测 E/A–D 与 RGB。先保持 OE 消隐验证时序。 | 每地址、每平面 64 个 CLK；每组一次 LAT；切地址及 LAT 时 OE 保持消隐；32 地址都出现，E 在 15→16 翻转；RGB 在采样沿前后稳定。 |
| E. 低亮度映射 | 从全黑开始，逐一测 RGB1/RGB2 的单行、单像素、四角及边界；记录 0/15/16/31 对应的两条物理行。 | 行对、左右移位方向、RGB 通道均有实际记录；无重复行、错色或明显串亮。实测结果回写映射。 |
| F. 全屏诊断 | 低亮度全红、全绿、全蓝、棋盘格、单行列游走，确认后再逐档提高全白占空比。 | 全 64×64 可寻址，颜色和位置正确；记录整帧频率、屏端最低电压、空白/纯色/全白电流以及持续运行温升；无异常掉压、供电限流、重影或 MCU 重启。 |
| G. 固件验收 | 由干净工作区构建并复测；验证错误、停止扫描与复位时消隐。 | 提交可复现构建命令、产物与 Flash/SRAM 报告、GPIO 清单、逻辑分析仪截图和实测参数；无硬件时标明待验收。 |

常见现象：

- **完全不亮：** 先查电源 CV/CC 状态、屏端电压、共地、IN 和 Pin 1；再查缓冲是否使能、OE 是否真的有短低脉冲、LAT/CLK 是否到灯板。基础波形正确仍不亮，再找 ICN2027 对应的模组资料或已知良好的同板控制波形。不要试套不明芯片的寄存器初始化。
- **隔 16 行重复或只有半屏：** 重点查 E/Pin 8 的连通与 15→16 边界，及 RGB2 三线；再排查地址映射。
- **方向反了或颜色错位：** 先用四角和六个单通道图案查线序；确认飞线正确后在 `panel_map` 修正方向/色序。
- **重影、随机闪点：** 测 OE 消隐窗口、行地址/LAT 顺序、CLK 振铃、地弹和负载压降；降低速度、增加保护间隔后复测。
- **接上 ST-Link 仍连不上：** 量核心板 3V3、查探针的 VTref 属性和 SWDIO/SWCLK 接法；用短线、低速 SWD、NRST 下连接。

首测记录建议字段：`板号 / 核心板与探针型号 / MCU供电 / IN与Pin1照片 / 5V电源限流 / 屏端电压 / 空白与全白电流 / CLK频率与脉宽 / LAT脉宽 / OE极性与点亮时长 / 32行对映射 / 整帧频率 / 构建版本 / 测试时间`。

## 9. 可直接复制到 Codex 的开发提示

```text
请在当前工作区为 STM32F103C8T6 开发 64×64 P2.5 HUB75E RGB 点阵屏驱动，
先读《STM32F103C8T6-HUB75E-64x64-开发交接.md》（或 docs/hardware-handoff.md）
和现有代码。板号 H-M-P2.5-6464-32S-I-2121-2012-V2.1，照片有 ICN2012、
ICN2027、74HC04。64×64、1/32 和常规双行 HUB75E 时序是首版工作模型；
实际行对、移位方向、色序、极性及专用初始化要求以实测为准。

硬件：我用 ST-Link 走 SWD（PA13/PA14），灯板单独用可调电源 5.0 V，
STM32/电平转换器/灯板/ST-Link 共地，HUB75E 16 针没有 5 V。
先核实灯板 IN、Pin 1、供电极性与两地针；灯板主电流不经过 STM32。
GPIO：R1/G1/B1/R2/G2/B2 = PA0/PA1/PA2/PA3/PA4/PA5，
CLK/LAT/OE = PA6/PA7/PA8，A/B/C/D/E = PB0/PB1/PB10/PB11/PB12，
HUB75E Pin 4、16 是 GND，Pin 8 是 E。14 路经两片 AHCT245 做 3.3→5 V。
如果装有文档中的可控三态电路，PB13 是 SHIFT_EN，高使能，初值低；
未装时使用明确配置的硬件方案，不能默认为复位期间已消隐。

先检查现有 .ioc、板型、可用构建链和用户改动；保留现有文件。
CubeMX：Serial Wire，推挽输出，PA8 初值高，其余信号初值低，
先写 GPIO 电平再切输出模式；默认以已确认的时钟配置工作。
保护消隐：启用缓冲前 OE 高，先移入全零；停止/故障路径先消隐。
需要暂停调试或接线时保持灯板关断或消隐。

第一版用 C 和 STM32Cube HAL 初始化，必要时用 BSRR 实现数据热路径。
先做 1 位每色低亮度诊断：32 行地址、每组移 64 列、RGB 六线并行、
消隐时换行并锁存、随后 OE 短脉冲；不先做 DMA、文字或多位灰度。
提供全黑、R/G/B 单通道、上下组独立、单行、四角、棋盘格；
有诊断方式标识帧起点，支持核对 E 位和边界。将板型、时序常数、
行列色序映射集中配置。不要套用其他驱动器初始化序列。

扫描验证后再做定时器行槽、RGB565 单缓冲、绘图和可调全局亮度，
随后根据实测决定灰度及 DMA。C8 以 64 KiB Flash、20 KiB SRAM 为硬预算；
保存链接 map 并说明峰值内存和最坏行时序。刷新率用整帧周期计算。
提交 .ioc 或可复现初始化配置、固件源码、编译与烧录说明、上电和测试记录。
软件能验证的实际运行并报告；没有实物、ST-Link 或仪器访问时，
明确列出待实测项，不把编译成功写成灯板已点亮。
```
